# まるサッカー

丸だけのオンラインサッカー。画像もフォントも 3D も使わない。
プレイヤーは丸を操作して、**ドリブル**して、**溜めて蹴る**。3対3・3分。

- **軽い**: クライアントは HTML + CSS + JS だけ（外部 CDN ゼロ、依存ゼロ）。サーバの依存も `ws` 1個
- **すぐ始まる**: 人が足りないぶんは BOT が埋めるので、1人で開いても必ず試合になる
- **サーバ権威**: 物理はサーバが回す。クライアントは自分の丸だけ予測して即座に動かす
- **Render 1サービス**で完結（静的配信 + WebSocket）。ランキングだけ Supabase（無くても動く）

```
server/     サーバ (Node)      index.js: HTTP+WS / room.js: 試合 / bots.js: BOT / store.js: 戦績
shared/     サーバとクライアントが同じものを読む物理・定数・通信フォーマット
public/     クライアント (そのままブラウザが読む ES Modules)
supabase/   schema.sql (貼るだけ)
test/       node --test で回る。ネットワークを含む通し確認もある
```

## うごかす

```sh
npm install
npm start          # → http://localhost:8080
```

`npm run dev` で `--watch` 付き。テストは:

```sh
node --test test/sim.test.js   # 物理・BOT・部屋 (ネットワーク不要, 0.5秒)
node --test test/net.test.js   # 実際にサーバを起動して HTTP/WS を叩く
```

## あそびかた

| | PC | スマホ |
| --- | --- | --- |
| 移動 | WASD / 方向キー | 画面左側をドラッグ（触った場所がスティックの中心） |
| キック | スペース / 左クリック | KICK ボタン |
| ダッシュ | Shift / 右クリック | DASH ボタン |

**キックは押しっぱなしで溜まる。離した瞬間に蹴る。**

### ゲーム性はどこにあるか

グラフィックが無いぶん、駆け引きは全部ルールに寄せてある。

- **ドリブルは「触る」だけ**。ボールはくっつかないので、走りながら押し出して運ぶ。
  速く走るほど大きく前へ転がる → 曲がりたければ減速するしかない
- **溜めシュートはリスクとセット**。溜めている間は移動速度が 62% に落ちる。
  強い一発を狙うほど、無防備な時間が伸びる
- **タックル**: ダッシュ中に敵に体当たりすると、相手は 0.4 秒動けなくなり、**溜めも消える**。
  ダッシュはスタミナ制（1回 30 / 毎秒 22 回復）なので、撃つ場所を選ぶ
- **横に走りながら蹴るとボールが曲がる**（マグヌス力）。壁際からゴール前へ巻ける
- **走っている勢いがシュートに乗る**。走り込みながら蹴ると同じ溜めでも速い
- **ゴールポストは硬い**。枠に当たれば跳ね返る
- **四隅は丸い**。角が直角だと、隅に入ったボールを押し出す立ち位置が「ピッチの外」に
  しか無くなって永久に取り出せなくなるため（人でも BOT でも起きる）。
  曲面なら少し斜めに押すだけで転がり出る
- 保険として、**6秒ボールがほとんど動かなければキックオフからやり直す**

数値はぜんぶ [`shared/constants.js`](shared/constants.js) の 1 ファイルに集めてある。
`PLAYER.kickMax` を上げれば強シュート、`BALL.damp` を下げればボールが止まりやすくなる。

### 部屋

- **クイックマッチ**: 人がいる部屋から順に相乗り。満室なら新しい部屋を作る
- **合言葉**: 同じ英数字を入れた人どうしが同じ部屋になる。URL に `?r=あいことば` でも入れる
- 各チーム 3 人ぶんの席があり、空きは BOT が埋める。人が入ると BOT が 1 体どく

## ネットコード

「軽い」を最優先にして、UDP を使わずに WebSocket だけでまとめてある。

| | 中身 | サイズ |
| --- | --- | --- |
| 入力 (C→S) | 30Hz、`seq / 方向 / ボタン` | **6 byte** = 180 B/s |
| スナップショット (S→C) | 20Hz、ボール + 全員の位置・速度・状態 | **6人で 88 byte** ≒ 1.8 KB/s |
| それ以外 | 参加・得点・名簿など | たまに JSON |

- 物理はサーバが **60Hz 固定ステップ**で回す。入力は「最後に届いたものを毎 tick 使う」ので、
  パケットを取りこぼしても次で上書きされるだけ（再送しない）
- 他人とボールは **100ms 遅らせて補間**して描く。20Hz でも滑らかに見える
- **自分の丸だけは予測**する。サーバとまったく同じ `shared/physics.js` をブラウザでも
  読ませているので、ズレは小さい。サーバの正解が届いたら差を**状態には即座に反映し、
  見た目には出さずに 0.1 秒ほどかけて溶かす**（画面が飛ばない）
- **蹴った瞬間は返事を待たない**。ローカルで描画位置にオフセットを足して先にボールを飛ばし、
  本物の軌道が追いついてきたらオフセットが消える。押した瞬間に反応が返る
- 誰もいない部屋は物理を止める（無料プランの CPU を食わない）

不正対策はしていない（改造クライアントは作れる）。身内やカジュアル用途を想定。

## Render にデプロイ

リポジトリのルートに [`render.yaml`](render.yaml) を置いてあるので、
**Dashboard → New → Blueprint** でこのリポジトリを選ぶだけでよい。
手で作る場合は Web Service をこの設定で作る:

| 項目 | 値 |
| --- | --- |
| Runtime | Node |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Region | `singapore`（日本から遊ぶなら一番近い） |

ポートは `PORT` 環境変数から読む（Render が自動で入れる）。WebSocket は追加設定なしで通る。

> **無料プランの注意**: 15 分アクセスが無いとスリープし、復帰に 30〜60 秒かかる。
> 「開いたら固まってる」ように見えるのはこれ。常時起動したいなら Starter（$7/月）にする。
> レイテンシは 1 リージョンぶんだけ乗る（東京から Singapore で片道 40〜70ms 程度）。

クライアントを別の場所（GitHub Pages など）に置きたい場合は、
`?server=https://xxx.onrender.com` を URL に付ければそのサーバへ繋ぐ。

## Supabase（ランキング・任意）

**未設定でもゲームは普通に遊べる**（戦績がサーバのメモリにしか残らないだけ）。

1. Supabase でプロジェクトを作る
2. SQL Editor に [`supabase/schema.sql`](supabase/schema.sql) を貼って実行
3. Render の Environment に 2 つ入れる:

   | Key | Value |
   | --- | --- |
   | `SUPABASE_URL` | `https://xxxx.supabase.co` |
   | `SUPABASE_SERVICE_KEY` | Project Settings → API → `service_role` キー |

試合が終わるたびに、サーバが `soccer_record()` を呼んで勝敗とゴール数を足し込む。
ランキングの閲覧はサーバの `/api/leaderboard` 経由なので、**ブラウザには鍵を一切渡さない**。
テーブルは RLS 有効・ポリシー無しにしてあるので、`anon` キーからは何も見えない。

プレイヤーの識別は端末の localStorage に持つ匿名 ID（`pid`）だけ。ログインは無い。

## API

| パス | 中身 |
| --- | --- |
| `GET /healthz` | `ok`（Render のヘルスチェック用） |
| `GET /api/rooms` | 人がいる部屋の一覧 |
| `GET /api/leaderboard?limit=50` | ランキング |
| `GET /api/config` | 物理・試合の設定（クライアントは使っていない。調整の確認用） |
| `WS /ws?room=xxxx` | 試合 |
